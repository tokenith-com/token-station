# TokenStation データベース更新の確認

リリース前レビュー。本番の基準 `c7288771` のデータベーススキーマ目標バージョンは 9、ローカル統合版 `678376a8` の目標バージョンは 11 です。統合版は初回起動時に未適用のマイグレーションを自動実行してからサービスを提供します。既存のデプロイスクリプトとデータベース接続を引き続き使用しても、マイグレーションは実行されます。

| バージョン | マイグレーション内容 |
| --- | --- |
| 10 | サブスクリプション OAuth のホストと登録情報を保存する `subscription_oauth_hosts` と `subscription_oauth_registrations` を作成 |
| 11 | Responses API の画像リソースを関連付ける `responses_image_store_bindings` と、有効期限のインデックスを作成 |

この 2 件のマイグレーションはマイグレーション台帳を更新します。SQL は既存の業務テーブルの列やインデックスを変更せず、既存の業務テーブルを削除しません。従来の起動時データ処理は引き続き実行されます。

`c7288771` が受け入れるスキーマは 8～9 のみです。データベースを 11 に更新した後、プログラムだけを戻しても旧版サービスは復旧できません。ローカルでは隔離された SQLite と PostgreSQL を使用して `9 → 11` と移行後の `db verify` を検証済みです。この確認時点では統合版は未デプロイで、本番データベースにも今回のマイグレーションは適用されていません。

## 確認事項

- 本番スキーマを 11 に更新してよいか。
- 更新を許可する場合、バックアップ、復元演習、およびロールバック時の切り替え後に書き込まれたデータの扱いを確認する。
- スキーマ 9 を維持する場合、`c7288771` を基準にテーブル追加を必要としない上流の変更を選び、スキーマ 9 のテスト用データベースで起動と主要 API を検証する。
